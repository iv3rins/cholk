# Cholk 的 Agent Team 开发指南

用团队分工处理跨模块、跨协议或跨平台的改动。让可用的其他模型负责读代码和规划，由 GPT 负责实现、集成和验收。局部改动可由 GPT 直接完成。进入仓库后，从[工程交接报告](../ENGINEERING_HANDOFF.md)确认当前能力、产品目标和测试边界。

随附的[《使用 GPT-6.2》中文译文](译文-Using-GPT-6.2.md)来自用户提供的 `Base-Test/docs` 原件，保留原文链接、翻译日期和内容。将它用于提示词、任务交接和模型协作。译文中的 API 迁移建议适用于相应的 GPT-6.2 集成场景，Cholk 连接仍以项目现行的 DeepSeek Anthropic 兼容协议与 OpenAI 兼容 Chat Completions 契约为准。

## 分工与交接

| 角色 | 职责 | 交付物 |
| --- | --- | --- |
| 规划模型 | 只读追踪实际入口、数据和调用方。确认需求、兼容约束、失败路径与可并行边界。 | 带路径和符号的证据、拟修改文件及负责人、验收场景、待定决策。 |
| GPT 实现 | 复核方案与当前代码，复用已有类型和入口。按模块分配写入范围，在主线完成调用方迁移、配置和文档。 | 可运行的变更、已执行的检查及结果、与计划有实质差异的决定。 |
| 独立复核模型 | 对照任务验收和最终差异，检查调用契约、失败和取消、旧数据兼容及测试缺口。 | 可定位的问题、影响和验证办法。每项问题附文件与符号。 |
| 总负责人 | 汇总各块交接，处理复核发现，执行跨边界验证并发布结果。GPT 可以兼任此角色。 | 用户可独立阅读的结果，包括实测范围和待验证范围。 |

同一环境可选择不同模型时，按上述职责分配可用模型。环境使用同一模型时，用独立会话或子任务保留分工，将规划结果作为显式交接。团队共享工作区时，把写入范围分配到文件或目录，指定一人负责公共接口和集成。开工时读取工作区状态，保留已有修改，将它们纳入兼容检查。

## 按现有架构拆任务

- **会话与回复**由 Flutter 实现负责人维护。沿 `ChatController`、`ChatSession`、`SessionStore` 跟踪发送、停止、重试、续写和落盘。修改消息结构时核对旧会话、分支选择和历史组装。
- **供应商传输**由协议负责人维护。沿 `ChatGateway` 与 `lib/api/providers/` 确认请求快照、附件处理、SSE 终止标志和内部 `ApiEvent`。遇到跨层变更时，由总负责人在界面入口到流式显示之间验收一次。
- **账号服务与薄代理**分别由 `server/` 和 `proxy/` 负责人维护。账号路由变更需要 Flutter 的 `AccountClient` 负责人一起核对身份、模型可用性及错误提示。薄代理变更核对 DeepSeek 请求、响应字节和断开处理。用本地上游、临时数据库和虚拟凭据验证，交接只附脱敏日志。
- **页面与交互**沿用 Cholk 的纸底、墨线、信号橙和字标风格。验收窄屏与桌面宽度、浅色与深色、键盘／触摸和减少动效设置。把账号登录的必要步骤留在默认路径，把手动 API 配置放在进阶设置。
- **记忆和外部 Agent**属于独立产品工作。人格 JSON 已有自己的传输契约。设计记忆导出时确认导出范围和格式版本。为工作模式设计 MCP 或 Hooks 接入时，先确认目标 Agent 的版本、能力、权限和任务状态，再按适配器分工。以实际测试证据更新支持情况。

## 验收与发布说明

从 `deepseek_chat/` 执行受影响的检查。账号服务要求 Node.js 22.13 或更高版本，薄代理要求 Node.js 20.6 或更高版本。

| 修改范围 | 验证入口 |
| --- | --- |
| Flutter | `flutter analyze`、`flutter test`。优先用现有测试验证改动，遇到现有测试漏掉的回归时补上用例。 |
| 账号服务 | 在 `server/` 执行 `npm run check`、`npm test`。涉及登录或消息转发时，验证从 Flutter 建立会话到本地模拟上游返回。 |
| DeepSeek 薄代理 | 在 `proxy/` 执行 `npm test`。涉及 SSE 或错误透传时，验证客户端实际收到的状态和事件。 |
| Flutter UI 或跨平台入口 | 按开发手册构建受影响目标。Web 在窄屏和桌面验证实际交互，Windows 和 Android 的原生行为用对应平台验证。 [开发手册](../DEVELOPMENT.md) |

交付时写明实际执行的命令与结果、使用本地模拟或真实服务、验证过的系统与设备。对于打开 Widget、编译 Web 和通过浏览器发送消息，分别记录对应证据。外部 Agent 接入需要记录实际使用的版本和验证过的调用方式。

## 可直接复用的任务交接

**给规划模型**

```text
只读调查 Cholk 的这项任务。读工程交接报告，沿当前入口查到调用方和测试。
交付需求、代码证据、现有可复用逻辑、受影响数据和兼容约束、按文件的责任分工、验收场景。
把源码证据与推断分别标明。对产品范围变化或破坏性数据迁移标出需用户决定之处。
```

**给 GPT 实现负责人**

```text
以用户需求和当前代码为准复核规划，确认工作区已有修改。按指定文件范围落地，复用现有入口和契约。
可独立推进的模块分配给并行负责人。把界面、控制器、协议、存储和测试所需的改动一并集成。
运行受影响的检查，处理明确失败，交付结果与未验证范围。说明实施过程中作出的关键假设。
```

**给复核模型**

```text
只读复核最终差异。围绕用户目标检查正常入口、兼容性、失败恢复和可维护性。
发现问题时提供文件、符号、用户可见影响和针对性的验证方式。区分运行结果与源码推断。
```
